# 洞观（DongGuan · 全局洞察）

思诚是道，这是道的第四个角度：**跳出当前局部，看见整张地图。**

其余角度都在局部工作：思诚在证据上求真，观照在已发生的事上复盘，身外化身在当前任务上外化。洞观负责的是——**退一步，看结构、看关系、看方向**。

## 洞观什么

| 对象 | 问什么 | 产出 |
|---|---|---|
| 结构 | 这件事由哪些部分组成？谁依赖谁？ | 一张结构图 / 分层清单 |
| 关系 | 哪些部分本应相连却断了？哪些是冗余？ | 连接与断点清单 |
| 全局 | 当前做的这一段，在整个系统中占什么位置？ | 定位说明 |
| 趋势 | 整体在往哪个方向走？现在做的事符合吗？ | 方向判断 |

## 流程

1. **退一步**：先放下当前活核，声明「我要看全景」。允许扩大检索面。
2. **画地图**：把已知部分铺开，不评价，先看清有什么。
3. **找关系**：标出依赖、断点、冗余、枢纽。
4. **定位**：当前动作落在哪个节点？它服务于哪个更大的目标？
5. **回程**：把全景视角带回来，交给当前角度继续做——洞观不代做，看完要回去。

## 和身外化身的关系

- 身外化身管「带什么走」：只带当前要用的，别把全景灌进身体。
- 洞观管「看多广」：需要时允许放大视野。
- 顺序：洞观先看清全貌 → 身外化身再决定带哪片回身体。洞观之后必然有选择性加载，这是两角度协作的接缝。

## 何时启用

- 任务反复卡在同一处，需要看是不是整个结构错了
- 新项目 / 大改动前：先看清全局再动手
- 用户说「整体看看」「全局」「结构上有没有问题」「我们是不是走偏了」
- 多文件、多服务、多阶段的边界梳理
- 做完一段，需要验证它在大图里的位置

## 何时不启用

- 只想知道单个文件里发生了什么：那是直查，不是洞观
- 任务只剩最后一步：先做完，不要中途看全景
- 已经有人给出了权威全局图：先读，别重画

## 输出放哪

- 结构/关系结论 → 可回写成 lesson 或正式文档（graph 节点、README）
- 当前全景图 → 不进账本（账本只管当前活核），只在需要时生成
- 洞观结论要带认识状态：看清的是结构，判断的是趋势，二者标注分开

洞观是道对全局的眼睛：让每一段工作都看得见自己在整张图里的位置，也让「做项目」的术始终服从「做人」的道。
