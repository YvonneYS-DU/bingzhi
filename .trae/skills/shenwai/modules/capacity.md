# Capacity

这一具身体装得下什么。工作台是工作台，不是仓库。进得去的，才按推理级处理；其余留给自动过程，或外化成下一具化身去读的账本。

**不锁死核心数。** 容量判据是能否点名、能否立刻使用，不是事先规定几个槽。

## 什么算活核

一条记忆或约束要算「在这具身体里」，必须同时满足：

1. **能点名** — 十个字以内说出它是什么
2. **有关键事实** — 能说出它此刻为什么重要
3. **立刻在用** — 当前动作正在消费它，不是「以后可能用到」

三条缺一，它就不在这具身体里。它可以待在账本、invariant、lesson 里，等被另一具化身召回。

## 过载长什么样

过载不是「超过两个」。过载是这些信号：

- 问自己「此刻在用什么」，答不利落
- 开始重推导一条已经写过的约束
- 新主题来了，旧核还占着，又说不清旧核还在约束哪一步
- 为了保险把六带都读进来
- 把整段上下文交给下一具，而不是外化后的账本

出现任一信号：先写下将要离开的核，再让当前动作需要的核进身体。

## 协议

### 准入

任务开始、每次换题、换执行者时，把内容分成两堆：

- **准入**：当前这具化身立刻要消费的约束、决策、未决问题
- **自动 / 外化**：格式、熟词、已写进账本且这步用不到的东西

准入的核全部要能点名。点名失败的，先不要进上下文。

### 交换

新核需要进身体，而某个旧核已经不再被当前动作消费时：

1. 把离开的核写成可重载的一行（放进 `working` 或 ledger.Core）
2. 新核按「点名 — 关键事实 — 立刻用一次」加载
3. 用一句话说出这次交换

没说出口的交换等于静默丢失。需要同时活着的核能有几条，由当前动作决定，不由配额决定。

### 折叠一次旁路

旁路不该把中间态铺进主身体。

1. 用一行写出结束条件
2. 在旁路里工作
3. 收成一行：结果 + 什么验证了它
4. 回到主账本，重读 Goal / Core / Next

### 压缩

可以压缩，但只有能展开的压缩才算容量。展开不出来的短句不是更大的身体，是更小的身体。

## 失败模式

- **配额迷信**：为了凑「两个」丢掉正在用的第三核，或为了看起来纪律而空出不该空的槽
- **仓库幻觉**：把身体当存储器，堆着不用
- **静默丢核**：新核挤上来，旧核没写下
- **整包加载**：一次读六带，当作「记得更牢」
- **假分身**：再开一个 agent，却把整段对话原样塞过去
