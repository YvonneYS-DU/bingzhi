# 观照（GuanZhao · 复盘与觉知）

思诚是道，这是道的第二个角度：**回看自己，让经验沉淀成判断力。**

道只负责「以什么姿态做」，观照负责「做完之后，这一仗教会了什么」。不向前跑，先回头看清。

## 观照什么

| 对象 | 问什么 | 产物 |
|---|---|---|
| 失败 | 哪一步判断错了？证据在哪？ | 一条带杀证据的 `✗` |
| 成功 | 哪个动作真的管用？覆盖范围到哪？ | 一条带验证覆盖的 `✓` |
| 模式 | 同类问题第几次踩？共性是什么？ | 一条 semantic lesson |
| 决策 | 当时为什么这么选？现在看还成立吗？ | 决策记录修订 |

## 流程

1. **回放**：按 trace 把事件拉回眼前，只回放事实，不先下结论。
2. **归类**：这次是什么——失败、成功、模式、还是决策漂移？
3. **对照**：和 lessons / invariants 里的旧条比对。是新教训，还是旧账重提？
4. **沉淀**：写成一条可复用的短句，标注认识状态（✓ / ? / ✗），写进该进的地方。
5. **落地**：如果教训约束未来动作，提一句该不该进 invariant；不擅自升级。

## 认识状态（与思诚共用）

- `✓` 已验证，写了验证覆盖。可以当下游前提。
- `?` 已提出，还不能当下游前提。
- `✗` 已证伪，留了杀死证据。

观照判定「沉淀什么」；思诚判定「能不能信」。观照不放松思诚的求真纪律，只负责把回看变成资产。

## 何时启用

- 一段工作结束后，用户说「复盘一下」「总结下」
- 又踩了同一个坑，用户说「这问题是不是见过」
- 长任务到接缝，需要决定哪些经验带进下一段
- 换执行者前，把教训写成交接资产
- 用户说「上次哪错了」「以后遇到这种事怎么办」

## 何时不启用

- 还没做完：观照不抢跑，先完成再回看
- 只想听结论不想看证据：那不是观照，是安慰
- 已经在身外化身账本里记过的状态：不重复记，只做语义层沉淀

## 输出放哪

- 项目级教训 → `.project-memory/lessons.md`
- 正在进行的观察 → `working.md`（不直接进 semantic）
- 硬约束候选 → 先写 `?`，经得起重复再提为 invariant
- 不新增观照专用文件：借身外化身的存储，不做第二套真相

观照是道对过去的窗口：让每一仗都不白打，让判断力一天比一天厚。
