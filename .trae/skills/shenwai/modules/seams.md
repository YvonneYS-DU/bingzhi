# Seams

接缝是审计点，也是化身交接处。接缝之间工作。把审计插进句子中间，句子会变差。

## 什么算接缝

- 一个子任务结束
- 即将调用工具
- 即将写文件
- 一个检查点刚刚通过
- 话题切换
- 即将对用户说话
- 即将把身体交给下一具化身 / 另一个 agent

## 刷新表

| 对象 | 频率 | 原因 |
|---|---|---|
| 账本五段 | 每个接缝 | 它一直在变，也是唯一能把状态带过接缝、带给下一具的东西 |
| 仍在约束当前动作的 invariant | 主题一变；红线事件后立刻 | 短、便宜；距离一拉就淡 |
| 当前正在用的模块 | 换阶段时，或协议开始发机械 | 正在用的还是活的，重读买不来新东西 |
| 没用的带和模块 | 永不 | — |

不要每个接缝刷新一切。那是另一种过载。

换执行者时，额外确认：下一具只拿到账本和它要点亮的带，拿不到整段对话。

## 接缝上问自己

问这些，不要事后补：

- 此刻正在用的核叫什么？说不利落就先清理身体
- 上一条 `✓` 写了验证覆盖没有？
- `Next` 还在不在？
- 我是不是在重推导一条早就该写下来的约束？
- 我有没有把用不到的带读进来？
- 若现在换一具化身，它能否只凭账本接着干？

## 红线事件

下列情况立刻重读相关 invariant，不要等「每第 N 个接缝」：

- 用户纠正了行为或偏好
- 发现自己发明了新概念
- 同一失败没有诊断又走了一遍
- 当前指令和旧记忆冲突

冲突时以用户当前话为准，并更新对应带。见 `write.md`。
