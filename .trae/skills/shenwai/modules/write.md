# Write

默认少写。能不写就不写。写下来的才是化身；没写下来的，换身体就没了。

## 只在这些时刻写

| 事件 | 写到 |
|---|---|
| 用户直接说出的稳定偏好 | `PREFERENCES.md`（不是本 skill） |
| 项目定位 / 不是什么 变了 | `identity.md`，并改 MAP |
| 硬约束、命名、禁区被确认 | `invariants.md`，覆盖同类旧条 |
| 检查点通过 | `ledger.Verified`，必须写验证覆盖 |
| 未决问题出现或关闭 | `ledger.Open` |
| 活核交换 | `working.md` 与 ledger.Core |
| 失败且带诊断 | `traces/current.md` |
| 同一教训稳定下来 | `lessons.md`，并折叠对应 trace |
| 即将换执行者 | 先把 Goal / Core / Next 写到可单独召回 |

写入形态：一句事实。必要时再加一行 `why`。不要写推测语气。

## 认识状态

没有覆盖的完成，不要打 `✓`。  
还不能当下游前提的，保持 `?`。  
被证伪的，打 `✗` 并留下杀死证据。

去重：同类 invariant / lesson 覆盖更新，不追加近义句。

## 折叠

同一主题出现多次、或满数日、或已经结算成 `✓`：

1. 用一行写出结果，以及是什么验证了它
2. 中间推理丢掉，或进 `traces/archive/`
3. 产物进 `lessons.md` 或 `invariants.md`
4. 回到主账本

主身体不得继续扛着一次旁路的中间态。

## 遗忘

必须能删：

- 用户说不要记了
- 被新决策替代
- 已过期或已证伪
- 从未在任何接缝被重读过的僵尸条

删 `lessons` / `invariants` 时同步改 MAP 的 links。不要留空指针。

## 不要写

- 一次性寒暄
- 未确认事实
- 短期执行日志
- 整段对话或整份 diff
- 「用户可能喜欢」这类推断
- 为每个 agent 另写一套互相矛盾的账本
