# Record Node — 记录节点

## 干什么

把这次改动记录到项目日志里。方便以后回头看"当时为什么这么改"。

## 输出格式

写入项目的 `CHANGELOG.md` 或 `.loopy/log.md`：

```text
## 2026-08-02

### feat: foo() 支持 D 场景模式

**原因**：用户需要在 D 场景下让 foo() 走不同逻辑。

**改了**：
- src/foo.py L42-58：新增 `mode` 参数，默认 "default"，兼容旧行为
- src/bar.py L23：传入 `mode="D"`

**验证**：测试全部通过，lint 无新增警告。

**注意**：如果以后加新 mode，在 foo() 的 MODE_MAP 里注册即可。
```

## 记录什么

```yaml
必须记录:
  - 日期
  - 改动摘要
  - 原因（为什么改）
  - 改了什么（文件+行号就行）

可选记录:
  - 验证结果
  - 注意事项
  - 相关知识（linking 到其他相关改动）
```

## 不做的事

- 不写"本次改动提升了系统可维护性"之类的评价
- 不写长篇大论
- 不分析用户工作习惯

## 核心规则

```text
记录目的是让未来的自己（或同事）能看懂当时为什么这么改。
写事实，不写评价。
每条记录 5-10 行足够。
```
