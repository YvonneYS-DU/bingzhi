# Loop Engine — 兜底机制

## 是什么

Loop 不是 graph 的一个节点。Loop 是监控 graph 的守护进程：

- Graph 正常跑 → Loop 不介入
- Graph 卡住了 → Loop 介入，强制推进

## 什么算"卡住" vs 什么是"合理问一次"

不是所有追问都是 bug。有两种追问：

### 合理追问（不用介入）

```yaml
合理追问:
  - 第一次遇到某个偏好选择（commit message 用中文还是英文？）
  - 用户指令确实有歧义，且默认方案可能导致大返工
  - 涉及安全的操作（force push？删数据库？）

处理方式：
  1. 给出默认方案，一句话说明假设
  2. 用户纠正 → 执行纠正 → 记录到 PREFERENCES.md
  3. 用户确认 → 执行默认
  4. 以后同类问题不再问，直接读 PREFERENCES.md
```

### 卡住信号（需要 Loop 介入）

```yaml
卡住信号:
  - 连续追问超过 2 次，项目没有实质性进展
  - 同一个偏好问题反复问（说明没记录 PREFERENCES.md）
  - agent 提出超过 3 个新概念/术语，但没有改一行代码
  - agent 在同一个节点停留超过 3 轮对话
  - 用户说："直接做"、"不用问了"、"随便"、"你决定"
  - agent 说："我需要了解更多"但已经问了 2 次以上
```

**特别注意：Grok 等模型容易过度解读用户意图，创造不必要的概念。一旦检测到 agent 在发明抽象概念而非改代码，loop 立即介入。**

## 偏好系统：问一次，记下来，永不再问

项目根目录的 `PREFERENCES.md` 是 agent 的行为偏好文件。agent 每次启动先读它。

### 工作原理

```text
第一次遇到偏好问题：
  问一次，给默认。
  用户回答后，自动追加到 PREFERENCES.md。

第二次遇到同类问题：
  直接读 PREFERENCES.md，不再问。

PREFERENCES.md 长什么样：
  不是 AI 分析的"工作习惯"。
  就是用户直接说的偏好，原样记录。
```

### 示例

```text
# 第一次
Agent: commit message 用中文还是英文？默认中文。
User: 英文
Agent: [改完代码后]
      [自动在 PREFERENCES.md 追加：]
      ## commit 风格
      - commit message 写英文

# 第三十次
Agent: [读 PREFERENCES.md，看到 `commit message 写英文`]
      [直接写英文 commit message，不问]
```

### PREFERENCES.md 只记录什么

| 记录 | 不记录 |
|------|--------|
| 用户直接说的偏好 | AI 推测的"用户可能喜欢" |
| 具体的行为规则 | 抽象的"用户倾向" |
| 反例："不要用 class，用 function" | 反例："用户偏好函数式风格" |

## Loop 介入后做什么

```yaml
介入策略:
  优先级从高到低:

  1. 直接执行默认方案:
     不再问，按最合理的默认路径推进。
     如果默认方案不对，用户会说，那时候再改。

  2. 给选项，不给开放问题:
     压缩为 2-3 个具体选项，用户点选即可。
     格式：
     "我判断你想做 A。如果不是，说 B 或 C 就行。我默认按 A 继续。"

  3. 降级节点:
     跳过卡住的节点，先做后面的。
     例如：verify 卡住了（测试环境有问题），先做 package 和 record。

  4. 最小化沟通:
     做完再说，不用每一步都确认。
```

## 示例

### 触发前（卡住了）

```text
Agent: 我理解你想重构 foo()。你是想用策略模式还是工厂模式？
      还是说你更倾向于适配器模式？
      你能描述一下你的设计意图吗？
User: 我就是想加个参数
Agent: 明白了，但加参数可能影响类的单一职责原则。
      你考虑过用依赖注入吗？
```

### Loop 介入后

```text
Agent: 好的，给 foo() 加 mode 参数，默认值兼容旧行为。
      我现在改。
      
      [改完]
      
      foo() 新增 mode 参数，bar() 传入 mode="D"。
      测试通过。要 commit 吗？
```

## 不做的事

- Loop 不是另一层分析
- Loop 不记录用户反馈
- Loop 不提炼工作习惯
- Loop 不生成报告

Loop 只做一件事：**让项目继续推进。**

## 核心原则

```text
能做就不问。
要问就问一次，记到 PREFERENCES.md，永不再问。
连续追问是 bug，不是 feature。

Grok 模型特别提示：
不要揣测用户深层意图。
不要发明概念。
用户说什么就做什么，用户没说的不要脑补。
```
