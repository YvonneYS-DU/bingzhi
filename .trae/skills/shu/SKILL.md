# 术（Shu）

这是做项目的方法层，与 `dao`（道）平行。

道管做人：求真、觉知、外化、洞观。术管做项目：把意图变成代码，把代码修对，把代码变好。

术从道出发，被道约束。冲突时道 > 术：项目目标可以换，做人的姿态不换。

## 七角度

| 角度 | 一句话 | 何时路由过去 |
|---|---|---|
| 实现 | 把意图变成代码 | 需求明确，要动手写 |
| 调试 | 从症状找根因 | 出错、异常、行为不符 |
| 测试 | 证明代码真的对 | 写测试、补覆盖、验收 |
| 审查 | 挑风险找问题 | 交付前自查、别人代码、合并前 |
| 重构 | 不动行为改结构 | 代码能跑但难维护、重复、命名差 |
| 设计 | 动手前想清结构 | 新模块、新系统、大改动前 |
| 周天 | 监督道术循环 | 跨角度长任务、检查断流、经验回流 |

## 大周天循环

术不是六角度排队上场，是一炉气在转。完整循环：

```text
道（做人姿态） → 术（六角度运转） → 观照（经验回流） → 道（更厚） → 术（更准）
```

- **道生术**：做人姿态流进项目，写代码时求真、觉知仍然在场。
- **术运角度**：设计→实现→测试→审查→重构，按需周转。
- **观照还道**：做完的教训回流成道，道因做事而更厚，再养下一轮术。

`zhoutian` 就是这个循环的监督者：只查「气有没有断」，不代做任何一格。

## 路由规则

- 只路由，不代做。命中的角度负责把事做完。
- 一次通常只点一个角度。要多个角度串行时，按依赖排：设计 → 实现 → 测试 → 审查 → 重构。
- 角度之间可以互相调用：调试出根因可能先重构再修复；审查发现问题可能回到实现。

## 何时启用

- 用户给出具体工程任务：写功能、修 bug、加测试、审代码
- 用户说「写一下」「报错了」「测一下」「review 一下」「这个代码太烂了」「先设计一下」
- 会话从道（方向问题）落到术（执行问题）的那一刻

## 何时不启用

- 是做人问题不是工程问题：路由回 dao
- 一步能核验的小事：直接做，不进术
- 已经在某个角度内部工作：不绕回总闸

## 和道的关系

| 道角度 | 在术层的落点 |
|---|---|
| 思诚 | 测试、调试的证据纪律：不猜测，先验证 |
| 观照 | 审查、重构后的复盘：让教训回炉 |
| 身外化身 | 长工程任务的接缝、账本、换执行者 |
| 洞观 | 设计、重构前的全局结构判断 |

术不新增身份，不建状态。它只做一件事：把工程任务按角度分类，然后路由到正确的方法。
