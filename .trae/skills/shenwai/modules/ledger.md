# Ledger

账本就是身外化身。它记 **现在已知什么**，不记待办清单，不记推理草稿。

下一具化身、下一个 agent，应该只凭这份账本接着干，而不是凭上一具身体里没写下来的印象。

五段，短到能在几秒内重读。读不完的账本等于没有。

```markdown
# Ledger

## Goal
## Core
## Verified
## Open
## Next
```

## 五段各管什么

| 段 | 写什么 | 怎么改 |
|---|---|---|
| Goal | 一句可检验的完成条件 | 任务边界变了就改 |
| Core | 当前这具化身正在消费的活核。每条：`名字 — 使它重要的那一个事实` | 只通过说出的交换改 |
| Verified | 编号、只追加。每条带验证方式和覆盖范围 | 不改旧条，只追加 |
| Open | 还没结算的问题，以及什么能结算它 | 关闭时写清对着哪条 Verified；编号不复用 |
| Next | 此刻唯一的下一步 | 永不为空 |

认识状态：

- `✓` 已验证，且写了验证覆盖。只有它能当下游前提。
- `?` 已提出，还不能当下游前提。
- `✗` 已证伪，且留了杀死证据。

这和思诚的 observed / inferred / unknown 同语义，只是落在化身上。思诚判定能不能信；账本判定下一具能不能接着用。

## 协议

1. `loop` 一开始就开账本。`fast` 不要开。
2. **每个接缝重读。** 不读的化身比没有更糟。
3. Core 不锁条数。但每条都必须仍被当前动作消费。不再消费的，换下去并写一行。
4. `Next` 空了 = 这具化身已经停用。要么写下下一步，要么承认这段 loop 结束。
5. 换执行者之前，必须先把五段写到能单独召回。
6. 没有文件系统时，五段活在对话里，每个接缝重述一遍。文件从来不是重点，重读才是。

## 什么不该进账本

- 推理过程
- 草稿段落
- 「做了什么」的流水
- 环境里已经在跟踪的任务项
- 上一具身体的完整上下文

账本回答的是：后来的步骤、后来的化身可以依靠什么，哪些问题还开着。任务列表回答的是：还剩什么要做。两套问题，互不替代。

## 失败模式

- 把账本当日记
- 把 `✓` 打在没有覆盖声明的完成上
- 只读最后一行 Verified，不读整份
- Core 变成愿望清单
- 为每个 agent 另起一套账本，导致真相分叉
